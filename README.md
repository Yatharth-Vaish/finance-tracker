# finance-tracker

Log an expense or income from Telegram in one message; it lands as a row in a Google
Sheet, with a Dashboard tab that charts your monthly cash flow automatically.

```text
You:  60 snacks
Bot:  Saved ✓ −₹60 · Expense · Food
      snacks
      From: Bank Account · GPay   For: Me
      Today: −₹60 net (income ₹0, expense ₹60)
      Spending power: Daily +₹9,940
      [↩ Undo] [Category: Food]
      [● Bank Account] [Credit Card] [Cash]
      [● GPay] [PhonePe] [Card]
      [● Me] [Partner] [Family]   (● = current choice; tap any name to change it)
```

No server, no hosting bill, nothing to keep running yourself: the whole backend is a
single Google Apps Script project bound to the Sheet, free at personal-use volume.

## Features

- **Understands plain phrasing** — with an optional free Gemini API key, messages don't
  need to fit a template: `"250 sent to me by my partner"` is correctly Income, and a
  message describing more than one transaction (e.g. someone paying from your card and
  reimbursing you elsewhere) gets split into the right number of ledger entries. Without
  a key, a regex parser handles the common patterns (`60 snacks`, `+50000 salary`) as a
  free fallback — see "LLM parsing" below.
- **Saves immediately, fixes come after** — no tap-to-confirm step. The bot saves on
  parse and replies with what it logged; a wrong guess is corrected with a tap on the
  confirmation (or `/undo`), not by blocking the save. This is what keeps a normal entry
  to about one poll cycle instead of two (see "Why polling, not a webhook" below).
- **Know where money moved and who it was for** — every entry records the account/card it
  went through, the payment method (UPI app, card, cash...) and the person it was for.
  Say it in the message (`250 gift partner gpay`) or tap it; the account and method you
  used last are pre-selected, so repeat purchases are usually one tap.
- **Transfers are not spending** — credit-card bills, SIPs and moves between your own
  accounts are logged as `Transfer` and kept out of the income/expense totals, so paying
  a card bill doesn't double count purchases you already logged.
- **Budgets, read two ways** — name a monthly allowance per account (e.g. "Daily ₹10,000
  from Bank Account"), optionally restricted to specific categories when two budgets
  share one account (Travel + Gifting both on one card, say). Each budget can be read as
  a **balance** (rolls over month to month — unspent carries forward, an over-budget
  month carries a deficit forward, never blocked or floored at zero — `/budget` /
  `/balance`) or as **spending power** (resets to the flat monthly amount on the 1st, no
  rollover — the auto-shown line after a save, and `/month`). Mark a budget `Public` to
  have its spending power shown automatically, safe to glance at in front of someone;
  everything else (and every budget's real balance) only shows via `/budget`/`/balance`,
  run deliberately.
- **One ledger, signed amounts** — income and expense share one table (`Ledger`), with
  amounts signed (+income / −expense), so cash flow is just a `SUM()`.
- **Auto-built Dashboard** — monthly income/expense/net tiles, a 12-month trend, and this
  month's spending broken down by category, account, person and UPI app, generated by one
  function call.
- **Commands** — `/today` (income/expense), `/month` (this month's public spending
  power, resets on the 1st), `/budget` or `/balance` (every budget's real rollover
  balance, private), `/undo`, `/help`.
- **Zero cost** — Google Apps Script + Google Sheets + Telegram's Bot API are all free;
  Gemini's API free tier is far beyond personal-use volume too.

## Why polling, not a webhook

Apps Script Web Apps always respond with an HTTP 302 redirect (to serve the response
body from a second URL). Telegram's webhook client refuses to follow redirects, logs
`"Wrong response from the webhook: 302 Found"`, and never delivers reliably — this is a
known incompatibility, not something fixable from the script side. So instead of a
webhook, a time-driven trigger calls `pollUpdates()` once a minute (the fastest interval
Apps Script allows). The tradeoff is up to ~60 seconds of latency per message instead of
instant push delivery.

## LLM parsing

`src/Gemini.js` sends the message plus your live categories/accounts/people to the
Gemini API and gets back structured JSON directly (constrained by a response schema, no
free-text extraction). It's told to name only accounts/people that actually exist and to
leave a field blank rather than guess; anything it still gets wrong is sanitized against
the real lists (`sanitizeLlmEntries` in `Parser.js`) before it can reach the Sheet.

It's entirely optional and fails safe: no `GEMINI_API_KEY`, an API error, or an empty
result all fall back to the regex parser (`parseEntry` in `Parser.js`) transparently -
the bot never goes silent because the LLM is down or unconfigured.

To enable it: get a free key at [aistudio.google.com/apikey](https://aistudio.google.com/apikey)
(no billing needed) and add it as `GEMINI_API_KEY` in Script Properties. `GEMINI_MODEL`
is optional (defaults to `gemini-2.5-flash`) if the default model name ever needs
bumping. Run `testGemini()` from the editor afterward to confirm the key and schema work
before trusting it inside the live bot - it logs the raw response.

One message can describe more than one transaction (`"partner paid 357 from zaggle
for her food and sent 357 back to me in my bank account"` → two `Transfer` legs). Each entry saves
independently; the confirmation for a multi-entry message only offers **Undo all**, not
per-leg correction - if a split comes out wrong, undo and resend more explicitly, or fix
the rows directly in the Sheet.

## Project layout

- `src/Parser.js` — pure text parsing (`"60 snacks"` → `{type, amount, category, ...}`) and
  the regex fallback parser, unit tested.
- `src/Gemini.js` — optional LLM parsing via the Gemini API; returns `null` on any failure
  so `Main.js` can fall back to the regex parser.
- `src/Telegram.js` — Bot API wrapper (send/edit messages, inline keyboards, `getUpdates`).
- `src/Ledger.js` — reads/writes the `Ledger`, `Categories`, `Options` and `Budgets` sheets.
- `src/Main.js` — `pollUpdates()`, called every minute by a time-driven trigger.
- `src/Setup.js` — `setupSpreadsheet()` builds the Ledger/Categories/Options/Budgets/Dashboard tabs and charts.

## One-time setup

### 1. Create the bot

Message [@BotFather](https://t.me/BotFather) on Telegram, run `/newbot`, and save the token it gives you.

### 2. Enable the Apps Script API and log in with clasp

1. Visit `https://script.google.com/home/usersettings` and turn on the Apps Script API.
2. `npx @google/clasp login` (opens a browser for Google OAuth; only needed once per machine).

### 3. Create your own bound Apps Script project + Sheet

`clasp create` refuses to run in a folder that already has an `appsscript.json`, so create it
in a scratch folder first and copy the generated script ID back into this repo. This makes
your own Sheet + script, separate from anyone else's:

```bash
mkdir -p /tmp/finance-tracker-clasp-init && cd /tmp/finance-tracker-clasp-init
npx @google/clasp create --type sheets --title "Finance Tracker"
cat .clasp.json   # copy the "scriptId" value
```

Back in this repo, create `.clasp.json` (gitignored on purpose — it's specific to your
own copy of the script, so it shouldn't be shared or committed):

```bash
cd finance-tracker   # wherever you cloned this repo
cat > .clasp.json <<EOF
{"scriptId":"PASTE_THE_SCRIPT_ID_HERE","rootDir":"src"}
EOF
npx @google/clasp push
```

Open the Sheet (the URL clasp printed in step 3, or find "Finance Tracker" in Google Drive).

### 4. Add your accounts and people (private), then run setup

The `Options` tab lists your accounts/cards (with the ways you pay from each, like
`UPI:GPay, Card`) and the people you spend on. Real names should never be committed, so
they live in a gitignored seed file:

```bash
cp LocalOptions.example.js src/LocalOptions.js   # then edit src/LocalOptions.js
npx @google/clasp push
```

`src/LocalOptions.js` is pushed to *your* Apps Script project and only seeds the `Options`
and `Budgets` tabs the first time setup runs on an empty tab (`LOCAL_BUDGETS` is optional —
see the comments in `LocalOptions.example.js` for the row format). After that, edit the
tabs in the Sheet. If you skip this, generic placeholder accounts/budgets are used.

In the Sheet: **Extensions → Apps Script**, then **Project Settings (gear icon) → Script Properties**, add:

- `BOT_TOKEN` — from BotFather
- `GEMINI_API_KEY` — optional, see "LLM parsing" above; without it, the regex parser
  handles everything

Back in the code editor, run `setupSpreadsheet` once (Google will ask you to authorize the
script — approve it). This builds the Ledger, Categories, and Dashboard tabs.

### 5. Start polling

Run `setupPolling` from the code editor (open `Main.js`, pick `setupPolling` from the
function dropdown, click Run), or use the **Finance Tracker → Start Telegram polling**
menu in the Sheet once you reload it. This clears any stale webhook registration and
installs a trigger that checks Telegram for new messages every minute.

No deployment step is needed — there's no web app, nothing to expose publicly.

### 6. Point the bot at your chat

Open a DM with your bot on Telegram and send anything. It replies with your chat ID
(may take up to a minute, since it's polled). Add a final Script Property:

- `ALLOWED_CHAT_ID` — the number it gave you

From now on, only messages from that chat are accepted.

## Everyday use

```text
60 snacks                       → expense, auto-categorized as Food
+50000 salary                   → income, categorized as Salary
1.2k rent                       → expense, 1200, categorized as Rent
250 sent to me by my partner → income (needs GEMINI_API_KEY; the regex fallback can miss this phrasing)
```

Every entry saves the moment it's parsed - there's no tap-to-confirm step. If something's
wrong, tap a name on the confirmation to correct it (category/account/method/person), or
tap **↩ Undo**. Whatever the message doesn't say is filled from your last entry.

```text
250 gift partner gpay        → For: Partner, paid with the GPay app
12000 credit card bill       → Transfer (not counted as spending)
24000 sip                    → Transfer
```

The words you can type (`partner`, `gpay`, `cash`...) come from the **Aliases** column of
the `Options` tab.

Commands: `/today` (today's income/expense), `/month` (this month's spending power for
`Public` budgets only — resets on the 1st, safe to glance at), `/budget` or `/balance`
(every budget's real rollover balance, private), `/undo`, `/help`.

## Development

```bash
npm test                 # runs test/parser.test.js with node's built-in test runner
npx @google/clasp push   # after editing anything in src/
```

`src/Parser.js` has a Node-compatible `module.exports` guard at the bottom so it can be
unit tested outside Apps Script; the rest of `src/*.js` depends on Apps Script globals
(`SpreadsheetApp`, `UrlFetchApp`, etc.) and can only really be exercised by running the
bot for real.

## Roadmap

Not built yet, in rough priority order:

- Per-leg editing for multi-entry messages (currently only "Undo all").
- A separate `Trades` sheet for stocks/IPOs (buy/sell date, qty, price, P&L), feeding
  realized gains into the Ledger as income.
- Recurring entries (salary, rent) logged automatically instead of by hand.
- The bot proactively warning when a budget is close to (or past) zero, instead of only
  showing balances when asked.
